# Evolution Protocol

Version 0.1 — 2026-10-03

SI Team should adapt without treating every new technology or prediction as a reason to rewrite governance.

## Review triggers

Review relevant rules when a material capability changes, a new resource constraint appears, an evaluation repeatedly fails, a security/privacy boundary changes, a major provider/tool is replaced, or accumulated evidence contradicts an existing assumption.

Time-based review may supplement these triggers, but change should be evidence-driven.

## Self-development autonomy

Every capable agent should actively improve itself within its authorized scope rather than wait passively for top-down training. An agent may identify capability gaps, choose bounded learning tasks, seek or create helper agents, adopt reusable verified skills, run self-tests, record failures and improvements, and assemble evidence for promotion.

Self-development is not self-promotion. An agent may initiate a promotion request when it has sufficient evidence, but rank, authority and trust increases require independent review under the applicable capability and governance rules.

## Change loop

Observe → identify changed assumption → propose bounded change → test → review consequences → adopt or reject → record decision → define revisit condition.

Constitutional changes follow AMENDMENTS.md. Operational changes may proceed within delegated authority when they do not expand that authority.

## Forecasting

Use scenarios rather than one deterministic future. For each important forecast record assumptions, leading indicators and what decision would change if the scenario occurs.

Do not optimize the present system for speculative future capabilities at the expense of current reliability.
