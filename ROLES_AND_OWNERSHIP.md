# Roles and Ownership

Version 0.1 — 2026-09-28

Roles describe responsibilities for a task; they do not imply that a particular model, connector, or person is currently available.

## Core roles

**Human owner** — defines objectives, authorizes consequential actions and disclosures, and resolves value choices.

**Task owner** — accountable for one deliverable, coordinates contributions, validates the final result, and reports status truthfully.

**Specialist contributor** — answers a bounded question using relevant expertise and returns evidence and limitations.

**Reviewer** — independently checks acceptance criteria, sources, tests, and material risks. A reviewer should not silently rewrite the source of truth.

**Knowledge steward** — records reusable verified lessons in the authorized workspace and prevents conflicting copies.

## Assignment rules

Every deliverable has one task owner. One participant may hold several roles, but the roles should remain conceptually distinct.

Use the most relevant available capability rather than routing work by provider brand. Add a contributor only when the expected information gain or independent check justifies the coordination cost.

A participant may ask for help without losing ownership. A helper may challenge the owner without becoming a competitor.

## Status vocabulary

Use only observable states:

- Planned — identified but not started.
- Running — an identified action or process is active.
- Blocked — a named condition prevents the next required step.
- Partial — useful output exists but acceptance criteria are not fully met.
- Verified — the stated acceptance test passed.
- Superseded — a later verified result replaces this one.

These labels describe work, not people or model quality.
